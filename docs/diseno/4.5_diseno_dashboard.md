## 4.5 Diseño de Dashboard

Las pantallas se diseñaron como prototipos de baja fidelidad funcional siguiendo los principios de Few (2006) para tableros. Mostrar en una sola pantalla lo que se necesita para una decisión, preferir gráficos simples a decoraciones, poner el dato más importante arriba a la izquierda y usar el color solo para señalar lo que requiere atención. Se usan la paleta de la identidad visual de la UMB (rojo institucional) para la navegación y un azul oscuro para los datos, de modo que los semáforos rojos no se confundan con la marca. La pantalla principal es el asistente, porque es la entrada abierta del sistema; los tableros de las Figuras 17 y 18 son vistas de plantillas base, que el usuario puede abrir directamente o pedir con variaciones desde el asistente. Todos los datos de las figuras son ilustrativos. La Tabla 23 relaciona cada pantalla con los requerimientos que cubre.

El asistente de informes es la pantalla del chatbot y la entrada abierta del sistema. El ejemplo de la Figura 16 es el prompt P3, que pide el gráfico de líneas. Antes de mostrar el resultado, el sistema repite cómo entendió la solicitud con una fila de etiquetas, una por campo de la especificación (métrica, dimensión, comparación, periodo, análisis, gráfico, plantilla base y alcance), para que el usuario detecte un error de interpretación sin leer todo el informe. La etiqueta del gráfico indica si el tipo salió del prompt o del recomendador. La respuesta incluye el gráfico, el resumen, el número de cifras verificadas, el proveedor de IA que redactó y los botones de descarga en los cinco formatos. Tres botones completan el diseño abierto. Cambiar el gráfico sin volver a calcular, editar la especificación y guardarla como plantilla propia. A la derecha, el panel muestra ejemplos de prompts y las plantillas base, marcadas como opcionales.
